# AgriSpectra-Q — Scientific Guardrails

**Document type:** Scientific language, claim-control, and release-integrity specification  
**Audience:** Frontend, backend, dashboard, report, presentation, marketing, ML, and scientific-review teams  
**Status:** Mandatory guardrails for the current proof of concept

## 1. Purpose

This document defines the scientific language and claims that every AgriSpectra-Q frontend, backend, dashboard, report, presentation, and marketing component must follow.

The objective is to prevent scientific overclaiming. Every user-visible statement must distinguish what was observed from what was model output, what is only a proxy analysis, what is an interpretation, and what remains future validation.

A useful internal rule is:

```text
OBSERVED RESULT
→ MODEL OUTPUT
→ PROXY ANALYSIS
→ INTERPRETATION
→ FUTURE VALIDATION
```

These categories must not be collapsed into one biological claim.

## 2. Core Scientific Principle

The current Live Matrix target is a **Spectral Anomaly Proxy**. It is not a field-labelled disease or pest target.

Therefore, the system must never automatically translate:

```text
spectral anomaly
        ↓
confirmed disease or pest
```

A spectral anomaly is evidence that a spectral observation departs from a reference or relative scene distribution. It is not, by itself, evidence of a confirmed biological cause.

The approved operational interpretation is:

> AgriSpectra-Q identifies spectral-anomaly priority candidates from real EnMAP data and provides evidence to support targeted field inspection. Field verification is required.

## 3. Evidence Classification

Every claim in a product surface should be assigned one of these evidence classes.

### 3.1 Observed result

An observed result is directly measured or read from an actual project artifact.

Examples:

- A scene contains 224 processed bands.
- Scene 3 contains 1,047,911 valid pixels.
- A live run produced 438 high-priority zones.
- A generated GeoTIFF has CRS `EPSG:32636`.
- The measured processing time for Scene 3 was 49.11 seconds in the recorded run.

### 3.2 Model output

A model output is a score, category, ranking, prediction, or metric generated by a model or processing engine.

Examples:

- Mean anomaly score.
- `HIGH PRIORITY` category.
- Zone rank.
- Mean F1.
- PR-AUC.
- ROC-AUC.
- Brier score.
- ECE.

A model output must not be described as a biological fact unless independent validation establishes that relationship.

### 3.3 Proxy analysis

A proxy analysis uses a measurable computational signal as an operational substitute for a question that has not yet been independently field-labelled.

Examples:

- Spectral Anomaly Proxy.
- Pixel-level proxy recall.
- Inspection-budget coverage.
- Relative percentile prioritisation.

Proxy results can support prioritisation experiments. They cannot be renamed as field-level disease detection or field inspection accuracy.

### 3.4 Interpretation

An interpretation explains what the output may mean operationally while preserving uncertainty.

Approved interpretation:

> This region is a spectral-priority candidate for field inspection.

Not approved:

> This region is infected.

### 3.5 Future validation

Future validation is evidence that the current PoC does not yet contain but may collect later.

Examples:

- Field polygons.
- Agronomist observations.
- Independent disease or pest labels.
- A blind fourth EnMAP scene.
- Aligned temporal sequences.
- Field-level outcome validation.
- Operational cost measurements.

Future validation must be labelled as future, planned, or not yet validated. It must not be written in the past tense.

## 6. Model Claims

### 6.1 Current final benchmark

The final six-model benchmark reports:

| Model | Mean F1 |
|---|---:|
| AgriSpectra-Q | 0.963985 |
| HSI-RF | 0.963141 |

The difference is:

```text
AgriSpectra-Q − HSI-RF = +0.0008447 F1
```

The paired bootstrap analysis used 20,000 replicates. The 95% confidence interval for the paired difference is:

```text
[-0.0012054, +0.0026803]
```

Because the interval crosses zero, statistical superiority over HSI-RF is not established.

### 6.2 Other benchmark findings

HSI-RF has the strongest PR-AUC and ROC-AUC in the final comparison. Adaptive Classical has the best Brier and ECE. These are metric-specific findings and do not create a single universal winner across every metric.

### 6.3 Approved benchmark sentence

Use this exact sentence when a concise scientific interpretation is needed:

> **AgriSpectra-Q achieved the highest numerical mean F1 in the final six-model benchmark, but its improvement over HSI-RF was not statistically established by the paired bootstrap analysis.**

### 6.4 Incorrect benchmark sentence

Do not write:

> AgriSpectra-Q significantly outperforms HSI-RF.

The current evidence does not support that claim.

### 6.5 Benchmark labels

All frozen model metrics must be labelled:

```text
FROZEN SCIENTIFIC BENCHMARK
```

Do not present a frozen metric as live performance unless the backend has actually executed that model for the selected request and recorded the new run.

## 7. Quantum Claims

The current quantum component is a **quantum-inspired or hybrid computational research layer**.

It is not evidence of quantum hardware superiority. No current result establishes quantum advantage, quantum supremacy, quantum speedup, or hardware-level superiority.

Approved wording:

- Quantum-inspired hybrid component.
- Hybrid quantum-classical research layer.
- Quantum-inspired feature transformation.
- Research component within the broader AgriSpectra-Q architecture.

Prohibited wording:

- Quantum advantage demonstrated.
- Quantum speedup achieved.
- Quantum model beats classical models because of quantum computation.
- Quantum hardware superiority.

The quantum component must remain secondary to the product value of spectral decision support. It must not be used to imply scientific superiority that the benchmark does not establish.

## 8. Live Matrix Claims

### 8.1 Approved sentence

> **The Live Matrix converts spectral anomaly scores into georeferenced priority zones and inspection recommendations.**

### 8.2 Incorrect sentence

Do not write:

> The Live Matrix detects diseased fields.

### 8.3 Required context

Whenever a Live Matrix map, zone, or score is shown, provide sufficient context to prevent biological overinterpretation:

```text
Spectral-anomaly prioritisation result.
Relative priority category.
Field verification required.
```

The Live Matrix output is an operational screening signal. It is not a confirmed diagnosis.

## 9. Threshold Claims

P50, P80, and P95 are scene-relative spectral prioritisation thresholds.

They are not:

- Disease thresholds.
- Pest thresholds.
- Biological severity thresholds.
- Confirmed field-stress thresholds.
- Treatment thresholds.

Approved labels:

```text
P50 relative spectral prioritisation threshold
P80 relative spectral prioritisation threshold
P95 high-priority spectral threshold
```

Prohibited labels:

```text
P95 disease threshold
P95 pest threshold
P95 severity threshold
```

The threshold values depend on the scene distribution and the run configuration. They must not be interpreted as universal biological cut-offs.

## 10. Field Validation Claims

The current PoC does not include field validation. This is an explicit limitation and a future next-phase validation item.

Approved wording:

> Field validation is not included in the current PoC. The current output is a spectral-anomaly prioritisation signal, and field verification is required.

Future validation may include:

- Field polygons.
- Ground observations.
- Agronomist assessments.
- Disease or pest labels.
- Blind external scenes.
- Field-level performance.
- Temporal persistence.
- Operational inspection outcomes.

Do not write that the system has been field-validated unless those activities have actually occurred and are documented in the current evidence package.

## 11. Business Claims

The current measurable operational value is **inspection prioritisation**.

Approved wording:

> The potential operational value is the ability to rank spectral-anomaly candidates and allocate limited inspection resources toward higher-priority areas.

Do not claim:

- Guaranteed cost reduction.
- Guaranteed yield increase.
- Guaranteed pesticide reduction.
- Financial ROI.
- Commercial revenue.
- Customer savings.
- Proven intervention value.

Possible future business metrics include:

- Inspection area reduced.
- Time saved.
- Scouting efficiency.
- Field-confirmed detection.
- Cost per validated intervention.
- Travel time per validated finding.
- False-alarm burden.
- Missed-finding rate.

These are future measurement objectives. They are not current results.

## 12. Temporal Claims

Do not imply temporal monitoring unless aligned temporal datasets are actually used.

The current three-scene Live Matrix run is a multi-scene analysis, not a validated temporal sequence. Different scenes must not be described as before-and-after observations unless their acquisition dates, spatial alignment, and temporal interpretation are explicitly verified.

Approved wording:

> The current PoC analyses real EnMAP scenes. Temporal monitoring remains future work unless aligned multi-date data are explicitly provided and validated.

Prohibited wording:

- The system tracks crop stress over time.
- The system predicts how disease will progress.
- The system detects early disease progression.

## 13. Generalisation Claims

The current experiments use three real EnMAP scenes. Do not claim broad global generalisation, all-crop validity, all-region validity, or universal robustness.

A blind fourth scene and field validation are future validation opportunities.

Approved wording:

> The current evidence is limited to the evaluated real EnMAP scenes and the documented spatial evaluation protocol.

Prohibited wording:

- Works globally.
- Generalises to all crops.
- Valid for every agricultural region.
- Guaranteed on unseen landscapes.

## 14. Robustness Claims

The previously invalid robustness block must not be used as scientific evidence. It must not be cited as validated robustness evidence in a dashboard, report, presentation, paper, product page, or marketing statement.

A robustness result may be shown only when:

1. The experiment is valid.
2. The input and perturbation protocol are documented.
3. The evaluation is reproducible.
4. The result is present in the approved evidence package.
5. The interpretation matches the actual experiment.

If these conditions are not satisfied, label the result as unavailable or omit it.

## 15. LOSO Claims

Do not claim complete six-model leave-one-scene-out superiority because complete LOSO was not implemented for all six models.

Approved wording:

> Leave-one-scene-out evidence is partial or model-specific and does not establish complete six-model LOSO superiority.

Prohibited wording:

> AgriSpectra-Q wins complete leave-one-scene-out validation across all models.

Any LOSO chart must identify which models, scenes, and metrics were actually evaluated.

## 22. Claim Construction Rules

Before publishing a statement, identify its subject, evidence type, scope, and limitation.

Use this internal template:

```text
CLAIM:
What exactly is being said?

EVIDENCE TYPE:
Observed result, model output, proxy analysis, interpretation, or future validation?

SCOPE:
Which scene, run, model, metric, and protocol does it describe?

LIMITATION:
What does the evidence not establish?

APPROVED WORDING:
What is the narrowest accurate sentence?
```

A claim should become more cautious when its scope becomes broader. A result on three scenes is not a global claim. A proxy recall value is not field recall. A numerical F1 difference is not statistical superiority.

## 23. Red Flag Checklist

A developer must review every new UI string, tooltip, chart label, report sentence, slide, or marketing claim before release.

### Claim and target

- [ ] Does the text identify the target as a Spectral Anomaly Proxy where relevant?
- [ ] Does it distinguish a spectral signal from a biological diagnosis?
- [ ] Does it state `Field verification required` near an operational recommendation?
- [ ] Does it avoid disease, pest, infected-field, and biological-diagnosis claims?

### Metrics

- [ ] Is the metric labelled with its source experiment?
- [ ] Is a frozen benchmark clearly labelled?
- [ ] Is a live result actually generated by the current run?
- [ ] Is uncertainty shown next to the claim?
- [ ] Does the text avoid calling a numerical difference statistically significant when the confidence interval crosses zero?

### Thresholds and maps

- [ ] Are P50, P80, and P95 labelled as prioritisation thresholds?
- [ ] Are map labels operational rather than biological?
- [ ] Does `HIGH PRIORITY` mean inspect first rather than disease?
- [ ] Is NoData distinguished from low priority?
- [ ] Are zone counts and coordinates read from actual output files?

### Quantum and architecture

- [ ] Does the text avoid quantum advantage, supremacy, speedup, and hardware claims?
- [ ] Is the quantum component described as quantum-inspired or hybrid research logic?
- [ ] Does it avoid claiming that quantum computation caused a proven performance gain?

### Scope and validation

- [ ] Does the statement stay within the evaluated three-scene scope?
- [ ] Does it avoid broad global generalisation?
- [ ] Does it avoid claiming field validation?
- [ ] Does it avoid claiming temporal monitoring without aligned temporal data?
- [ ] Does it avoid citing the invalid robustness block?
- [ ] Does it avoid claiming complete six-model LOSO superiority?

### Business and deployment

- [ ] Does it describe operational prioritisation rather than proven financial ROI?
- [ ] Does it avoid guaranteed cost, yield, pesticide, or revenue claims?
- [ ] Are future business metrics labelled as future?
- [ ] Does it distinguish a proof of concept from a production-validated service?

### Release decision

- [ ] Has a scientific reviewer checked the wording?
- [ ] Has the source artifact or run been identified?
- [ ] Can the claim be reproduced from project files?
- [ ] Is the narrowest accurate wording used?
- [ ] Is any uncertainty visible to the intended user?

## 25. Release Ownership

The frontend owns visible labels, cards, tooltips, legends, empty states, and error copy. The backend owns API field names, status messages, error responses, and run metadata. The report and presentation owners own scientific summaries and limitation statements. The ML and scientific owners own metric definitions and experiment interpretation.

All owners share responsibility for preserving the same terminology. A safe backend field name can still be undermined by an unsafe frontend label. A scientifically correct report can still be undermined by a marketing headline. The guardrails apply across the complete product surface.

## Scientific integrity release gate

A release may pass the scientific integrity gate only when all of the following are true:

- [ ] Every user-visible claim is classified as an observed result, model output, proxy analysis, interpretation, or future validation.
- [ ] The current target is identified as a Spectral Anomaly Proxy where applicable.
- [ ] No current output is labelled confirmed disease, pest, infected field, biological diagnosis, or field-confirmed stress.
- [ ] Live Matrix outputs are described as georeferenced spectral-priority zones and inspection recommendations.
- [ ] P50, P80, and P95 are labelled prioritisation thresholds, not biological thresholds.
- [ ] Frozen benchmark metrics are clearly separated from live experiments.
- [ ] The exact benchmark sentence is used when summarising AgriSpectra-Q versus HSI-RF.
- [ ] The +0.0008447 F1 difference and crossing 95% confidence interval are not presented as statistical superiority.
- [ ] HSI-RF’s PR-AUC and ROC-AUC position and Adaptive Classical’s Brier and ECE position are not omitted when the full comparison is presented.
- [ ] Quantum language is limited to quantum-inspired or hybrid computational research terminology.
- [ ] No quantum advantage, supremacy, speedup, or hardware superiority claim is present.
- [ ] Field validation is identified as absent from the current PoC.
- [ ] Broad global generalisation is not claimed from three real EnMAP scenes.
- [ ] Temporal monitoring is not claimed without aligned temporal datasets.
- [ ] The invalid robustness block is excluded from scientific evidence.
- [ ] Complete six-model LOSO superiority is not claimed.
- [ ] Business language describes potential operational value and does not claim proven financial ROI.
- [ ] Every map uses operational priority labels and avoids biological labels.
- [ ] Evidence and limitations appear near the decision rather than being hidden.
- [ ] The red flag checklist has been completed for all new UI, dashboard, report, presentation, and marketing text.
- [ ] A scientific integrity reviewer has approved the final wording.
